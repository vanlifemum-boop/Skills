Ich habe Hermes Agent als Docker-Container auf diesem Server laufen.
  Hermes hat einen Befehl "hermes dashboard", der ein lokales Web-UI
  zur Verwaltung von Config, API Keys und Sessions startet (Default
  Port 9119, gebunden an 127.0.0.1). Da Hermes auf einem Server laeuft,
  komme ich vom PC zuhause nicht ans Dashboard ohne SSH-Tunnel. Bitte
  richte das mit Tailscale ein, damit ich es dauerhaft vom Browser auf
  meinem PC erreichen kann.

  Anforderungen:
  - Das Dashboard exposed API Keys -> es darf NICHT oeffentlich
    erreichbar sein (kein Reverse-Proxy-Eintrag, keine Port-Mappings
    auf der oeffentlichen Server-IP). Tailscale ist die einzige
    Bruecke nach aussen.
  - Das Dashboard soll als eigener, persistenter Service laufen
    (nicht via `docker exec`, der bei Container-Restart weg ist).
  - Aenderungen nur additiv (z.B. docker-compose.override.yml oder
    ein Sidecar-Setup) - originale Compose-/Config-Dateien nicht
    modifizieren.
  - Vom PC will ich das Dashboard per Hostname (Magic DNS) erreichen,
    z.B. http://hermes-dashboard:9119

    Schritt gehst.

    Setup an und mach mir einen Vorschlag, bevor du etwas aenderst.
  - Ich habe noch keinen Tailscale Account. Erklaere mir vollstaendig
    und in eigenen Schritten:

  - Den Auth Key trage ich selbst ein, damit er nicht im Chat landet.
